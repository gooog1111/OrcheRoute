# OrcheRoute Android

> Общий статус всего проекта: [PROJECT_STATUS.md](../PROJECT_STATUS.md).

Android-оболочка использует тот же статический интерфейс, что WebUI и Desktop,
но отдаёт файлы непосредственно из APK через AndroidX `WebViewAssetLoader`. HTTP-сервер и
публикация интерфейса в LAN отсутствуют.

Go-пакет `mobilecore` собирается в `app/libs/mobilecore.aar`. APK содержит
Android `VpnService`, встроенный Mihomo и переносимое Go-ядро.

Текущая версия — `0.5.5` (`versionCode 23`), minSdk 26. Тестовая APK собрана для
`arm64-v8a`. Insets строки состояния, выреза и
нижней навигации передаются интерфейсу нативно.

Сборка выполняется скриптом `build-apk.ps1` из корня Android-проекта. Скрипт
также проверяет, что каталог Next.js `_next` и CSS действительно попали в APK.

Результат: `dist/OrcheRoute-0.4.6-debug.apk`. Это debug-сборка. В ней есть
локальный Android API bridge, запрос системного VPN-разрешения, foreground
`VpnService`, встроенный Mihomo, gVisor stack, передача TUN fd и
`VpnService.protect` для исходящих сокетов. Без выбранного узла используется
диагностическая конфигурация `MATCH,DIRECT`.

На Android 13+ приложение явно запрашивает разрешение на уведомления. При первом
запуске также открывается системный запрос на исключение OrcheRoute из
оптимизации батареи (энергосбережение устройства целиком не отключается).
Активный VPN работает как foreground service: постоянное уведомление показывает
«VPN работает» и позволяет полностью остановить VPN кнопкой «Выключить».

В 0.2.0 добавлены локальные обычные и BlackTemple-подписки, ручное обновление,
разбор VLESS/VMess/Trojan/Shadowsocks, реальные имена узлов, ручной выбор и
перезагрузка Mihomo с выбранным сервером. Ссылки и параметры подключения
остаются в приватном хранилище приложения и не возвращаются списочными API.

В 0.2.1 добавлены встроенные аварийные источники EbraSha и Au1rxx, два
параллельных HTTPS URL-test для каждого кандидата, сохранение задержки и
отбраковка неответивших узлов. На одну подписку равномерно выбирается до 120
кандидатов, чтобы публичный список из тысяч записей не занимал устройство на
часы. Маршруты Direct/Proxy/Block, действие по умолчанию, домены, CIDR,
IP-диапазоны, порты и протоколы сохраняются локально и входят в конфигурацию
Mihomo. Для доменных правил включены fake-IP DNS и sniffer.

В 0.2.2 добавлены обязательные `default-nameserver` и
`proxy-server-nameserver` для конфигураций с `respect-rules`; это исправляет
отказ запуска Mihomo после сохранения мобильных маршрутов.

В 0.3.0 экран компонентов получает фактическую версию встроенного Go-модуля
Mihomo, наличие, размер и время GeoIP/GeoSite. Ручное GEO-обновление скачивает и
валидирует обе базы и восстанавливает предыдущую пару при ошибке. Периодическое
обновление выполняет Android `JobScheduler`: задача ждёт сеть, сохраняется после
перезагрузки и использует выбранный интервал. Встроенное ядро не подменяется
загруженным бинарником и обновляется только вместе с новой APK OrcheRoute.

В 0.4.0 добавлен сетевой транспорт без root: автоматический выбор сети либо
фиксация Wi-Fi, мобильной сети или Ethernet через `VpnService.setUnderlyingNetworks`.
Для Direct, Proxy, VPN-underlay и Bootstrap сохраняются отдельные DNS-профили;
они передаются встроенному Mihomo вместе с настройками cache, H3, hosts и IPv6.
При включённом IPv6 Android TUN получает IPv6-адрес и маршрут `::/0`. Недоступные
серверы во вкладке «Основная» скрыты по умолчанию и раскрываются отдельной
кнопкой со счётчиком.

Проверка сохранённых мобильных серверов выполняется по всему разобранному
набору без прежней выборки в 120 узлов. Конвейер показывает реальный прогресс
`TCP → URL-test по настраиваемому списку адресов → два speed-test` и использует соответственно
128, 80 и 6 параллельных работников. Ссылки URL-test добавляются, редактируются
и удаляются в разделе «Квалификация»; сервер должен успешно пройти большинство
из них. Перед speed-test пробная загрузка проверяет
доступность тестового файла через чистое соединение. Если текущий белый список
его не пропускает, speed-test явно помечается пропущенным, а прошедшие TCP/URL
узлы не отбрасываются. При полном отказе сохраняется прежний рабочий набор.
Автоматический режим выбирает аварийный узел при отсутствии доступных основных;
принудительная работа только через аварийный пул включается отдельной опцией.

В 0.4.1 в модалку добавления подписок и серверов добавлено сканирование QR.
Системный экран Google Code Scanner возвращает распознанную строку в тот же
импортёр, поэтому для QR действуют обычное распознавание формата и проверка
дублей. Приложение не запрашивает собственное разрешение на камеру; модуль
сканера предоставляют Google Play services.

Для проверки пропускной способности используется
`https://cachefly.cachefly.net/10mb.test`. Сначала чистое соединение загружает
диапазон 256 КиБ, чтобы понять, доступен ли тест при текущих ограничениях сети.
Затем каждый дошедший до speed-test сервер дважды загружает файл размером 10 МиБ.

В 0.4.2 обработчик встроенных файлов отличает сегмент обхода пути `..` от двух
точек внутри допустимого имени. Это исправляет запуск React, когда Next.js
создаёт chunk с именем наподобие `0pi2cq79xc-d..js`.

В 0.1.7 отключение отправляется самой службе через `ACTION_STOP`. Она закрывает
Android TUN и Mihomo до вызова `stopSelf()`. Основной `ParcelFileDescriptor`
остаётся у `VpnService`, а Mihomo
получает отдельный fd. При выключении закрываются оба дескриптора, поэтому
Android должен сразу снять системный VPN-профиль.
