# Архитектура Android OrcheRoute

Публичные методы `mobilecore` остаются стабильной JSON/gomobile-границей. Они
не содержат бизнес-логику и только декодируют запрос, вызывают один слой и
кодируют результат.

Поток данных:

```text
Android input
  -> physical network binding (without Internet/allowlist classification)
  -> parser
  -> validator
  -> subscription mapper
  -> routing
  -> constructor
  -> transport
  -> Android VpnService
```

## Границы слоёв

### Parser

Разбирает тело подписки и share-ссылки в нормализованные узлы. Не выполняет
HTTP-запросы, не сохраняет данные, не проверяет доступность и не строит маршруты.

### Validator

Проверяет подписки, политики квалификации, DNS и сетевые профили. Не исправляет
входные данные молча и не имеет побочных эффектов.

### Subscription mapper

Удаляет дубли между подписками, сохраняет принадлежность узла источнику и
сохраняет принадлежность узла подписке. Android показывает один список серверов,
сгруппированный по источникам; признак `group` старых подписок сохраняется для
совместимости данных. Не парсит протоколы и не тестирует сеть.

### Routing

Компилирует `direct`, `proxy`, `block`, порты, протоколы, GeoIP и GeoSite в
платформенно-нейтральные правила. Не запускает Mihomo.

### Constructor

Получает только проверенные узлы, DNS-профиль и скомпилированные правила и
строит итоговую конфигурацию Mihomo. Не выбирает сервер и не открывает TUN.

### Transport

Единый интерфейс запуска/остановки Mihomo, TUN, TCP/URL/speed-проб и счётчиков
трафика. Не парсит подписки и не принимает решения о пулах или маршрутах.

### Android adapter

`VpnService`, разрешения Android, foreground notification, файловые дескрипторы
и lifecycle. Политики выбора узла и построения конфигурации здесь отсутствуют.

## Правило зависимостей

Зависимости направлены только слева направо. Parser, validator, mapper и routing
не импортируют Android или transport. Constructor не управляет transport.
Transport не импортирует parser, mapper или routing. Android вызывает фасад и
transport, но не дублирует бизнес-правила.

### Connectivity

На Android `ConnectivityMonitor` используется только для выбора физической
сети, к которой привязываются защищённые сокеты транспорта. URL-пробы и
классификация `normal`/`allowlist`/`offline` выключены. Смена Wi-Fi и мобильной
сети не меняет выбранный сервер и не выключает VPN. Выбор underlay остаётся
системной задачей Android; если физический транспорт исчез, соединение может
стать недоступным, но пользовательское состояние «VPN включён» сохраняется.
Открытое приложение удерживает экран включённым; фоновая служба не управляет
блокировкой экрана.

### Ручной выбор и проверки

Android хранит один основной список серверов. Он включает узлы включённых
встроенных источников и добавленных пользователем подписок. UI группирует
серверы по подписке, позволяет проверять одну группу либо весь список. Явное
обновление подписки загружает и квалифицирует её серверы. Квалификация обновляет
оценку и доступность, но не переключает работающий VPN. Неудачная проверка не
снимает ручной выбор. Недоступный по последней проверке сервер также можно
выбрать вручную и попробовать подключить.

При обновлении со старой версии выбранный сервер сохраняется; режим выбора
становится ручным. Если выбранного сервера нет, запуск показывает ошибку и ждёт
выбора пользователя. Сетевой монитор, health-check и результаты обновления
подписок не выбирают замену. Общее Go-ранжирование остаётся подсказкой в списке,
а не политикой автоматического переключения Android.

Кнопка выключения сбрасывает сохранённое намерение `service_desired`. Ошибка
транспорта или уничтожение службы системой его не сбрасывают. При терминальной
ошибке FreeTURN UI показывает неисправность и предлагает вручную повторить
подключение к выбранному серверу. Если upstream сохранил хотя бы один поток,
Android TUN не пересоздаётся. Если не осталось ни одного потока, сама библиотека
FreeTURN может завершить сессию после отклонённой CAPTCHA; приложение не может
сохранить рабочий трафик без нового соединения.

### Редактор списка

Удаление сервера касается только текущего снимка: следующая проверка его
подписки может вернуть узел. Активный сервер нельзя удалить, пока VPN включён;
для полной очистки списка также нужно выключить VPN. Подписки при очистке
сохраняются. Отдельные старые массивы и признаки группы остаются в приватном
хранилище для безопасного обновления и возможного отката APK, но Android UI
представляет только один список.

Внутреннее уникальное `proxy.name` остаётся идентификатором Mihomo. Android UI
показывает отдельно подпись из ссылки либо пару «протокол · адрес». Название
добавляемого источника необязательно и при отсутствии выводится из его типа или
адреса подписки.

Создание, редактирование, включение и изменение набора встроенных подписок
сохраняют конфигурацию без автоматического сетевого теста. Загрузка и проверка
выполняются отдельными кнопками «Обновить» и «Проверить» для одной подписки
либо кнопкой проверки всего списка.

Пользователь всегда выбирает автоматический парсер. Внутренний адаптер
`standard` или `blacktemple` определяется при явном обновлении источника.
BlackTemple не определяется по имени подписки, домену или подписи сервера:
кандидат с непрозрачным токеном получает этот тип только после успешного ответа
специального протокола. Неуспешная проверка оставляет обычный HTTP-результат и
не превращает его в ошибку обновления.

### Обновление Android-приложения

Android читает только опубликованный `latest release` публичного репозитория
`gooog1111/OrcheRoute`. Release-asset для Android arm64 содержит `codeNN` в
имени; `NN` обязан совпадать с `versionCode` APK. Перед передачей системному
установщику приложение проверяет размер и SHA-256 из GitHub API, package name,
внутренний `versionCode` и совпадение сертификата подписи с установленным
OrcheRoute. Установка остаётся явным действием пользователя; при необходимости
Android отдельно запрашивает разрешение на установку из этого источника.
