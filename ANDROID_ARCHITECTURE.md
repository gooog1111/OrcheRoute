# Архитектура Android OrcheRoute

Публичные методы `mobilecore` остаются стабильной JSON/gomobile-границей. Они
не содержат бизнес-логику и только декодируют запрос, вызывают один слой и
кодируют результат.

Поток данных:

```text
Android input
  -> connectivity (independent physical-network state)
  -> parser
  -> validator
  -> subscription mapper
  -> routing
  -> constructor
  -> transport
  -> Android VpnService
```

## Границы слоёв

### Parser

Разбирает тело подписки и share-ссылки в нормализованные узлы. Не выполняет
HTTP-запросы, не сохраняет данные, не проверяет доступность и не строит маршруты.

### Validator

Проверяет подписки, политики квалификации, DNS и сетевые профили. Не исправляет
входные данные молча и не имеет побочных эффектов.

### Subscription mapper

Удаляет дубли между подписками, сохраняет принадлежность узла источнику и
формирует модели основного, аварийного и whitelist-пулов. Не парсит протоколы и
не тестирует сеть.

### Routing

Компилирует `direct`, `proxy`, `block`, порты, протоколы, GeoIP и GeoSite в
платформенно-нейтральные правила. Не запускает Mihomo.

### Constructor

Получает только проверенные узлы, DNS-профиль и скомпилированные правила и
строит итоговую конфигурацию Mihomo. Не выбирает сервер и не открывает TUN.

### Transport

Единый интерфейс запуска/остановки Mihomo, TUN, TCP/URL/speed-проб и счётчиков
трафика. Не парсит подписки и не принимает решения о пулах или маршрутах.

### Android adapter

`VpnService`, разрешения Android, foreground notification, файловые дескрипторы
и lifecycle. Политики выбора узла и построения конфигурации здесь отсутствуют.

## Правило зависимостей

Зависимости направлены только слева направо. Parser, validator, mapper и routing
не импортируют Android или transport. Constructor не управляет transport.
Transport не импортирует parser, mapper или routing. Android вызывает фасад и
transport, но не дублирует бизнес-правила.

### Connectivity

Независимо от состояния Mihomo и Android TUN параллельно проверяет физическую
сеть и возвращает ровно одно состояние: `normal`, `allowlist` или `offline`.
Платформенный адаптер только привязывает сетевой запрос к физической сети;
набор проб и классификация находятся в общем Go-слое. На Android монитор
обязан использовать `Network.openConnection()`: так к выбранной физической
сети привязываются и DNS-разрешение имени, и HTTP-соединение. Одного
`VpnService.protect()` для монитора недостаточно, поскольку он применяется к
готовому сокету и не гарантирует обход TUN отдельными сокетами DNS-резолвера.
Наличие подключённого Wi-Fi или мобильного интерфейса само по себе не считается
доказательством белых списков.

`normal` подтверждается настроенным open-internet URL и хотя бы одним из двух
независимых якорей; отказ одного якоря не переводит исправную сеть в whitelist.
Если это условие не выполнено, но отвечает хотя бы одна проба, состояние
классифицируется как `allowlist`. `offline` означает, что не ответила ни одна проба. Открытое Android-приложение
удерживает экран включённым; фоновая VPN-служба на блокировку экрана не влияет.

На Android единственным владельцем сетевых проб является `ConnectivityMonitor`.
Он реагирует на callback изменения физической сети, выполняет контрольную
проверку по таймеру и хранит последний подтверждённый снимок с временем и
ошибкой. `VpnService`, контроллер и обновление подписок только читают снимок и
никогда не запускают проверку самостоятельно.

Whitelist-пул сохраняется между переходами сети и используется повторно до
исчерпания. Полная проверка не очищает предыдущий рабочий пул заранее, сверяет
снимок `ConnectivityMonitor` после каждого батча и прекращается при выходе из
`allowlist`. Пользователь может отменить проверку через API/UI; отмена
кооперативная и завершается после текущей группы сетевых тестов.
Whitelist-операция явно помечается в API, поэтому кнопка остановки не зависит от
промежуточного текста connectivity. После отмены UI немедленно показывает
`cancelling` и опрашивает завершение операции, не ожидая общего таймера. Пользователь также может вручную запустить
формирование пула, когда монитор уже подтвердил `allowlist` и VPN включён.

### Редактор пулов

Android API поддерживает удаление отдельного сервера из текущего снимка
основного, аварийного или whitelist-пула. Это не постоянный запрет: следующая
проверка либо обновление исходной подписки может добавить тот же сервер снова.
При удалении активного сервера контроллер выбирает следующий доступный; если
whitelist-пул опустел, VPN останавливается с понятной ошибкой и не запускает
сканирование автоматически.

Внутреннее уникальное `proxy.name` остаётся идентификатором Mihomo. Android UI
показывает отдельно подпись из ссылки либо пару «протокол · адрес». Название
добавляемого источника необязательно и при отсутствии выводится из его типа или
адреса подписки.

Создание, редактирование, включение и изменение набора встроенных подписок на
Android только сохраняют конфигурацию. Они не запускают сетевую операцию и не
блокируют следующее редактирование; загрузка и проверка выполняются отдельными
кнопками «Обновить» и «Проверить». Автоматические проверки failover/whitelist
остаются независимыми от редактора.

Пользователь всегда выбирает автоматический парсер. Внутренний адаптер
`standard` или `blacktemple` определяется при явном обновлении источника.
BlackTemple не определяется по имени подписки, домену или подписи сервера:
кандидат с непрозрачным токеном получает этот тип только после успешного ответа
специального протокола. Неуспешная проверка оставляет обычный HTTP-результат и
не превращает его в ошибку обновления.

### Обновление Android-приложения

Android читает только опубликованный `latest release` публичного репозитория
`gooog1111/OrcheRoute`. Release-asset для Android arm64 содержит `codeNN` в
имени; `NN` обязан совпадать с `versionCode` APK. Перед передачей системному
установщику приложение проверяет размер и SHA-256 из GitHub API, package name,
внутренний `versionCode` и совпадение сертификата подписи с установленным
OrcheRoute. Установка остаётся явным действием пользователя; при необходимости
Android отдельно запрашивает разрешение на установку из этого источника.
